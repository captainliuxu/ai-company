- **期望行为**: 默认语音风格应与角色设定和陪伴产品体验一致，至少默认不应全部是男音。
- **发现时间**: 2026-05-30

✅ 已修复 — 2026-06-01 — TASK: BUG-FIX-006
- 验证结果: 复用既有 Review 通过记录；`/api/v1/voice/health` 返回的默认 `tts_voice` 已不再是男性默认声线，`/api/v1/voice/tts` 在省略 `voice` 或传 `default` 时都可正常返回音频。
- 修复摘要: 将运行环境中的默认语音切回更符合当前角色体验的女性声线，并保持现有 JSON 契约、播放链路与文本聊天主链路不变。

- **期望行为**: AI 回复应更短、更自然，减少长篇大论，整体节奏更像即时陪伴聊天。
- **发现时间**: 2026-05-30

- 修复摘要: 强化了默认短回复约束，让安抚型角色优先轻量接话、短句回应；SSE 流式表现、角色差异和自然聊天感未回归。

## BUG-009

- **功能编号**: 8.1
- **严重程度**: Critical
- **描述**: 聊天页录音后的语音转写失败，前端提示 `422`，用户无法把录音内容转成文字回填输入框。
- **复现步骤**: 1. 进入聊天页 2. 点击录音按钮并完成一段录音 3. 停止录音，等待前端调用 `/api/v1/voice/stt` 4. 页面提示转写失败，状态码为 `422`
- **期望行为**: 录音上传后应成功调用语音转写接口，并把识别出的文本回填到输入框；至少不应因请求字段不匹配而返回 `422`
- **发现时间**: 2026-06-01

✅ 已修复 — 2026-06-01 — TASK: BUG-FIX-009
- 验证结果: 独立 Review 已确认前端上传字段名与后端 `/voice/stt` 契约对齐，运行时请求不再因字段名问题返回 `422`。
- 修复摘要: 将前端 `transcribeAudio()` 的 multipart 字段从 `file` 改为 `audio`，消除了 `STT` 请求在 FastAPI 参数绑定层被直接拦下的问题。
- 复测备注: Review 在 synthetic 音频样本上还观察到上游 `503` 文本缺失响应，因此建议继续用真实录音做一次用户复测，确认完整转写链路是否已恢复。

## BUG-010

- **功能编号**: 8.1
- **严重程度**: Critical
- **描述**: 语音转写在修复 `422` 后仍失败。页面报错为 `Speech-to-text provider returned HTTP 400: Unsupported audio format... (503)`，说明录音文件已上传到后端，但 provider 仍拒绝当前音频格式。
- **复现步骤**: 1. 进入聊天页 2. 点击录音按钮并完成一段真实录音 3. 停止录音，等待前端调用 `/api/v1/voice/stt` 4. 页面提示 `Unsupported audio format... (503)`
- **期望行为**: 浏览器录音生成的常见 MIME 类型应被后端正确识别并以受支持的文件扩展名转发给 `STT provider`，不应因 MIME/扩展名推断错误被当作不支持格式。
- **发现时间**: 2026-06-01

✅ 已修复 — 2026-06-06 — TASK: BUG-FIX-010
- 验证结果: 发布前复核确认后端已兼容带 codec 参数的浏览器录音 MIME，且用户在本地真实浏览器中确认语音输入可用。
- 修复摘要: `voice_service.py` 已增加 MIME 归一化与扩展名推断兼容，避免 `audio/webm;codecs=opus`、`audio/ogg;codecs=opus` 等输入回落为不受支持的 `bin` 扩展名。
